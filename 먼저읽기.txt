WorkHub v4를 VS Code에서 확인·수정하기

열기
VS Code → 파일 → 파일에서 작업 영역 열기 → WorkHub-v4.code-workspace를 선택합니다.
또는 이 폴더에서 터미널로 code -n .\WorkHub-v4.code-workspace 를 실행합니다.
Power Platform 확장 설치 없이도 TypeScript·React·JSON·YAML을 열어 볼 수 있습니다.

폴더 역할
WorkHub: 수정할 원본 PCF 프로젝트입니다. React/TypeScript, Tailwind CSS, 데이터 모델을 포함합니다.
Canvas-v4: 정상 열림이 확인된 v4 .msapp을 그대로 압축 해제한 구조 확인용 폴더입니다.
WorkHubSolution: PCF 배포용 솔루션을 빌드하는 프로젝트입니다.
Original: 정상 열림이 확인된 v4 .msapp의 변경 없는 복사본입니다.

주요 파일 (이 문서의 경로는 현재 폴더 기준)
WorkHub/WorkHub/App.tsx: 대시보드, 목록, 상세, 등록 폼, 댓글, 활동 로그 UI
WorkHub/WorkHub/index.ts: PCF 초기화, 크기 처리, 입력값 반영, 선택 ID 출력
WorkHub/WorkHub/ControlManifest.Input.xml: PCF 이름·버전·입출력 속성
WorkHub/styles/input.css: 수정할 Tailwind 기반 스타일 원본
WorkHub/WorkHub/_const/seed.ts: 시연용 데이터
WorkHub/WorkHub/_service/demoService.ts: 등록·수정·댓글·로그 처리
WorkHub/WorkHub/_scheme/work.ts: Zod 데이터 모델·검증
Canvas-v4/Src/Screen1.pa.yaml: Canvas 화면에 WorkHub PCF 하나를 배치하는 정보
Canvas-v4/Controls/4.json: v4에서 수정한 PCF 내부 정의를 포함한 화면 직렬화 정보

로컬 실행 (VS Code 터미널의 작업 폴더를 WorkHub로 지정)
npm ci
npm run build:css
npm run start:watch

npm ci는 새로 복사한 소스 폴더의 첫 설치 때 사용합니다. 의존성은 기존 lock 파일을 따릅니다.
이미 사용 중인 원본 개발 폴더에서 의존성이 설치되어 있다면 다시 설치할 필요는 없습니다.
테스트 화면은 Power Apps Studio가 아닌 PCF 로컬 테스트 호스트입니다.
호스트의 크기를 Width 1366 / Height 900 정도로 설정하면 전체 화면을 보기 편합니다.

Tailwind 클래스나 styles/input.css를 계속 수정할 때는 별도 터미널에서 다음 명령을 실행합니다.
npm run build:css -- --watch

수정 코드 확인·프로덕션 빌드
npm run typecheck
npm run build:release

Power Apps에 수정 반영
PCF 코드를 수정·빌드하는 것만으로 기존 .msapp 안의 코드가 자동 변경되지는 않습니다.
일반적인 반영 순서는 다음과 같습니다.
1. ControlManifest.Input.xml의 PCF 버전을 올립니다.
2. PCF와 솔루션을 Release로 다시 빌드합니다.
3. 회사 환경에 업데이트된 PCF 솔루션 ZIP을 가져옵니다.
4. Canvas 앱을 닫았다가 다시 열고 코드 구성 요소 업데이트를 적용합니다.
5. 앱을 저장하고 필요하면 게시한 뒤, .msapp 복사본을 다시 내려받습니다.

이 프로젝트의 솔루션 빌드는 WorkHubSolution 폴더에서 다음 명령을 사용합니다.
dotnet build -c Release
PCF 빌드는 Node.js/npm, 솔루션 빌드는 .NET SDK 및 Power Platform 빌드 도구가 필요합니다.

Canvas 내부 파일을 다룰 때
이 앱의 복잡한 UI는 Canvas 기본 컨트롤로 나뉘어 있지 않고 PCF App.tsx 안에 구현되어 있습니다.
.msapp 안에는 원래의 App.tsx 대신 빌드된 bundle.js가 들어 있습니다.
Canvas-v4/Src의 pa.yaml은 구조 확인용이며, 직접 수정해 재압축하는 방식은 일반적인 편집·배포 경로가 아닙니다.
Microsoft 문서상 pa.yaml은 앱 로드에 사용되지 않고 내부 JSON도 안정된 공개 소스 형식이 아닙니다.
따라서 UI·기능 수정은 WorkHub 원본 소스에서 하고, Canvas 배치·수식 수정은 Studio에서 진행하세요.
현재 패키지는 회사 환경에 자동 업로드하거나 설정을 바꾸는 작업을 실행하지 않습니다.
